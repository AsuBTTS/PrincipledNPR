# Toon Shading 后端适配调研记录

日期：2026-10-28。状态：**已补完 73 张隔离 GPU 捕获及 12 项有界数值/图像检查，详见 [GPU 实验报告](ToonGPU/Report.md)。** 本文保留源码调查的推导与候选映射；实际执行条件、通过范围和反例以该报告为准。完整 Toon Adapter 和生产门禁仍未验收。

## 结论与决策边界

我们应继续把着色模型作为可配置的后端选择，而不是把 Toon BSDF 固定为系统唯一模型。统一的艺术参数保留引擎无关含义；后端适配器基于选中的模型、资源和实测环境报告每项能力，不能静默将不支持的参数当作成功。当前优先验证原生 Toon BSDF 和必要的局部扩展；这只是实验路线，不是生产选型通过。具体着色模型切换如何表达、编译和持久化仍需后续设计，不能假定当前系统已经具备该能力。

已有 C++ 绑定与 Surface 组合不等于完整 Resolver、Toon Adapter 或运行时语义切换。本文未改动它们。原始语义、默认值与高级参数继续以 `Documentation/Schemas/NPRParameterContract.v1.json` 为准。

## 源码路径与算法

以下路径均相对于 `E:/Unreal Engine/UE_5.8/Engine/`，行号适用于上述 CL：

- `Source/Runtime/Engine/Public/Materials/MaterialExpressionSubstrate.h:860`：实验性 Toon 节点；BaseColor、Metallic、Specular、Roughness、Normal、EmissiveColor、PatternUVs、Anisotropy、Tangent 与 ToonProfile。声明默认 BaseColor 0.18 灰、Metallic 0、Specular/Roughness 0.5；声明值并非实际资产值。
- `Source/Runtime/Engine/Classes/Engine/ToonProfile.h:24`：Diffuse/Specular RGB 曲线、偏移纹理/强度/尺寸、阴影消光与排线、间接光强度、间接镜面曲线及 experimental include-shadow。Profile 标注不要运行时更改，属于实验性资源。滑块范围与硬约束不同：偏移强度 UI 0–1 但仅 ClampMin 0；UV 尺寸 UI 1–100 但仅 ClampMin 1；Shadow Extinction 单位 1/m，硬范围 0–100、UI 0–10，内部换算为 1/cm。曲线编辑视图 0–1 并不自动证明所有曲线值硬钳制为 0–1。
- `Shaders/Private/Substrate/SubstrateToonBSDF.ush:67` 的 `SubstrateToonEvaluateCommon` 是本次最重要的直接光证据；`Shaders/Private/ToonProfileCommon.ush:15` 采样曲线纹理，支持独立 sampler 时为双线性钳制。Profile 图集构造见 `Source/Runtime/Engine/Private/Rendering/ToonProfile.cpp:26`。因此硬阶跃仍受到有限纹理分辨率与采样过滤影响，需要测量。
- `SubstrateToonBSDF.ush:16` 对 PatternUV 两轴分别饱和到 [0,1] 并编码 12 bit，Profile ID 编码 8 bit；偏移采样 `ToonProfileCommon.ush:84` 使用 `frac`，接缝和精度需要实测。这是编码宽度，不保证 256 个用户 Profile 都可分配。
- `SubstrateEvaluation.ush:2106` 附近对间接漫反射、镜面分别乘 Profile 的间接强度。间接镜面量化还依赖 `r.Substrate.Experimental.ToonReflectionQuantizationEnabled=1`；工程当前为 0。`ShaderCompiler.cpp:4155` 将其写入 Shader define，不可把它当普通 MID 参数即时切换。`LightRendering.cpp:2768` 说明 unified diffuse 开关不是运行时切换项；工程当前为 0。

### 明暗与投影的数值例子

在 `SubstrateToonEvaluateCommon` 中，令 `n = Context.NoL`，表示该灯与表面法线的点积；`t = TransmittanceShadow` 是代码使用的阴影透射值，既受引擎阴影路径影响，也可能经过排线。无偏移时，先计算 `u = 0.5n + 0.5`。不包含阴影时取 `Ramp(u)`，并将漫反射乘以 `t`；包含阴影时取 `Ramp(u*t)`，该项不再额外乘 `t`。两者还乘光源衰减和颜色等项。

例如 `n=0.4`、`t=0.5`，二值 Ramp 在 0.5 分界且暗亮分别为 0.2、1：关闭时采样 0.7，结果相对系数为 `1×0.5=0.5`；开启时采样 0.35，系数为 `0.2`。这个手算只解释公式，不是 GPU 结果；`t=0` 且 Ramp(0) 非零时不应假定输出必为零。对零尺寸单方向光、无偏移且关闭 include-shadow 的坐标，阈值 `tau` 对应 `(tau+1)/2`，半宽 `w` 对应 `w/2`；光源形状、过滤、AA 和阴影使最终可见位置仍需标定。

直接镜面先计算粗糙度保护后的 GGX 分布与能量查表；矩形灯走另一分支。非矩形分支 Fresnel 和 visibility 的调用在该函数中被注释；取镜面值平均后饱和并采样 SpecularRamp，最后乘 SpecularColor、表面阴影、NoL、衰减和灯色。故粗糙度、角度、灯型和色阶共同决定高光，不能用 `1 - roughness` 作为高光角宽的通用等价公式。

## 参数能力判断

判断规则：直接支持必须有语义与表现的实测。下表保留源码调查阶段的候选划分；后续 GPU 已验证部分原生响应存在，但没有把它升级为统一语义全域直接支持。尤其负阈值的最终外观受自投影抑制，见新报告。“自定义”只表示指定严格语义缺少已确认公开入口，不预判具体实现成本。

| 艺术需求 / 现有语义 | 候选接口和判断 | 待验证或缺口 |
| --- | --- | --- |
| `TerminatorDotCenter` | 适配候选：DiffuseRamp 位置按上述坐标换算 | 单灯坐标成立不证明最终画面精确；阴影、偏移与面光源条件须分测 |
| `TerminatorDotHalfWidth` / Softness | 适配候选：曲线过渡区半宽 w/2 | 图集、过滤、AA、显示分辨率的有效软硬范围未测 |
| 二阶、多阶、连续 Ramp / 明暗色 | 适配候选：Profile RGB DiffuseRamp 曲线 | 曲线采样、色空间、暗色与 BaseColor 相乘、灯色和多灯累加后的最终色彩均未验证；非独立绝对输出色 |
| `SpecHalfAngleRad`、`SpecEdgeSoftness`、`SpecPeakScale` | 适配候选：Roughness、SpecularRamp 曲线和颜色拟合 | 角宽、亮度、边缘耦合，跨视角和灯型未标定；无独立已验证大小/硬度/强度旋钮 |
| 高光颜色 | 适配候选：RGB SpecularRamp 与 SpecularColor 相乘 | 不是与材质金属度/F0 完全独立的最终颜色；HDR/动态范围及间接镜面分开测 |
| BaseColor / Normal / Roughness | 节点可接原表面数据，MID 可改已暴露的图参数 | 数据输入存在不证明输出与 Default Lit 相同；Normal 影响受光与镜面，Roughness 影响镜面；需逐项缓冲及视觉对照 |
| 真实投射 / 自阴影 | 原生 shadow/transmittance 路径和可选 include-shadow；消光单位 1/m | 光源、遮挡、VSM/CSM、几何距离和排线需分离测试；消光系数 0 不是关闭透射 |
| 方向、点、聚光、天空及 Lumen | 官方宣布支持各光源类型、天空光、Lumen；源码有直接及间接项 | 工程各灯、遮挡隔离及 Lumen 路径均未验收；天空/间接不等于逐灯 Ramp 等价 |
| `MacroNormalBlend` | 有资产提供宏法线时可用材质节点预处理 | 依赖真实输入，缺输入不可声称支持 |
| `FaceCriticalAzimuthTerminatorPerLight` | 严格逐灯替换：需自定义能力；PatternUV 偏移仅近似候选 | 普通 Surface 材质图不提供一般逐灯 NoL/visibility 替换接口；主光桥接须测接缝、量化与多灯副作用 |
| `HairShiftAngleRad` / 全视角角域瓣 | 独立 shift 和严格参考形状需自定义能力 | Tangent/Anisotropy 是候选近似，不证明独立 shift；改变共享 Normal 会影响其他分量 |
| Rim / Outline | 保留现有独立模块；Profile 无对应字段 | 历史共存证据限定在原测试范围，角色、多槽、动画待测 |

Epic 对 5.8 的官方能力声明见 [5.8 发布说明](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-8-release-notes)，API 见 [ToonProfile](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UToonProfile) 和 [Toon 节点](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UMaterialExpressionSubstrateToon-)。这些文档是能力线索，不替代目标工程实测。

## 资源、动态更新与槽位

节点引用 Profile；`MaterialInstance.h:671` 有 Profile override 字段，`MaterialInstance.cpp:5416` 按覆盖与父实例查找；`MaterialInterface.cpp:2196` 将 Profile 更新传给渲染代理。渲染内部 setter 不等于公开可用的 Blueprint/MID 运行时 Profile setter，本次未发现经验证的运行时热替换接口，不能推断切换必然无需编译或无卡顿。Profile 本身按引擎注释视为不可在运行中修改；建议预制 Profile 和材质实例、预加载后切换材质包，再实际测 Shader/PSO、cook 和稳定性。

标量、向量和纹理若在材质图中暴露为参数，UE MID 可动态写入；本项目 `NPRStyleBindingComponent.cpp:118`、`:252`、`:279` 分别提供部分表面和 Rim 参数绑定。Profile 曲线不是普通 MID 标量。`ApplyPackage` 按槽先验证并创建实例再设置材质，但多个槽、不同 Profile 和两个角色之间的隔离/动态切换尚需专门 GPU 验证；不同槽引用同一 Profile 时更不应通过修改共享资源实现独立控制。

## 隔离实验原计划与后续门禁

以下是源码阶段制定的实验计划；目前已在独立工程完成各类最小 GPU 对照，实际覆盖与未执行项目见 [GPU 报告](ToonGPU/Report.md)，不能把整张生产门禁表都标为通过。CSM、完整角色遮挡门槛、硬件 Lumen、冷 DDC、Cook、100 次预热切换和生产性能仍待后续执行。每组应保存引擎 CL、GPU/驱动、RHI、运行时 CVar、材质与 Profile 参数、相机、曝光、AA、灯光和阴影设定，并记录真实 HDR/缓冲。

1. 固定单方向灯、禁用环境与投影，以 `tau=-0.5/0/0.5`、多个 half-width 和二阶/三阶/连续 RGB 曲线扫角度；用 HDR 截面和颜色记录边界、单调性、最窄可见过渡。对照 `(tau+1)/2`，不能只凭截图目测。
2. 固定法线角度放置可移动遮挡物，分别开关 include-shadow，并固定无排线/消光；再固定遮挡移动光源。分离 `N·L` 与阴影变化，检查假色 Ramp 和受光强度，VSM、CSM 分开记录。
3. 分别只启用方向、点、聚光，再两灯共存并遮挡其中一灯；环境全关。单独测天空光黑/均匀及 Lumen 红墙反弹，保留 Default Lit 装置对照；屏幕/软件/硬件追踪、反射另列条件。检查间接尺度 0/1，不将直接光结果外推到 GI。
4. 固定视角/灯方向，网格扫描 Roughness、SpecularRamp、颜色和强度，再改变视角/灯型；用 HDR 计算高光半宽、峰值和边缘，记录无法独立控制的耦合。改变 BaseColor/Normal/Roughness 做分项与缓冲对照。
5. 两材质槽与两角色使用不同预制 Profile/MIC，分别写 MID 参数及切换包，记录相邻槽串扰、Profile 身份、100 次预热切换和编译/PSO；分别与现有 Rim、Screen/Hull Outline 组合。单独测试冷/热 DDC 和 cook，避免清除用户全局缓存。

每组应记录前提、步骤、原始图与数值、实际结果、限制和失败记录，运行完成前不填 Pass。UE 官方 [UE-388460](https://issues.unrealengine.com/issue/UE-388460) 报告 5.8 中 DDC 命中时 Toon 宏传播问题，页面当前标记未解决、目标 6.0；目标 5.8.3 是否复现仍未测。

## 后续路线比较

| 路线 | 覆盖与代价 | 风险 |
| --- | --- | --- |
| 原生 Toon BSDF | 复用引擎直接光、曲线与间接路径；初始工程成本较低 | 实验性版本依赖；统一语义、参数独立性和跨灯质量未验收 |
| 原生 + 局部扩展 | 优先复用原生，针对实测缺口添加材质函数或确需的渲染能力；适配成本中等且按缺口递增 | 材质图不能随意读取逐灯信息；扩展可能需要引擎阶段、增加维护和跨版本测试 |
| 自定义 Toon 后端 | 可按冻结需求设计独立语义和逐灯处理；控制范围更大 | 管线、阴影、GI、性能和升级维护成本最高，必须重建或对接并逐项验收 |

最小 GPU 矩阵已完成，下一阶段应基于已测条件实现并标定 Generic Adapter 子集，再补齐 Generic、阴影、GI、运行时生产门槛。遇到严格需求缺口且无法通过节点实现，再评估独立 Shader 阶段或自定义后端。所有后端保持可选择，不将某一模型重定义为统一语义本身。
