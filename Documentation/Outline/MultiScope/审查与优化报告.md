## 原实现与设计

实施前的审计表、实际渲染路径、引擎源码依据及方案见 [多粒度审查与设计](../多粒度审查与设计.md)。二进制资产审计见 [Index.json](AssetAudit/Index.json)：11 份材质/实例导出包含父链、材质输出、节点输入和 Material Function。没有修改 EndfieldRender 原资源，也没有根据《原神》的未确认内部实现作结论。

原插件的执行单位是“一个 SkeletalMeshComponent 中的一个材质槽”，并非 Actor、独立 Section 或完整角色。新增路径由 `UNPROutlineActorComponent` 管理角色逻辑分组，复用原 Settings、Preset 和三份材质。

## 为什么共享槽 Section 需要门禁

UE 5.8 的 `ShowMaterialSection` 最终更新 HiddenMaterials[UseMaterialIndex]；SectionIndex 用来查询 LODMaterialMap，不是单独的几何 Section mask。源 Primitive 的 Stencil 也不携带 Section ID。

本实现读取 Skeletal 的 RenderSections + LODMaterialMap，Static 的各 LOD RenderData.Sections，向调用方提供真实映射。无法隔离的选择明确报错，不静默扩大作用范围。若要支持共享槽 Section，需要在内容管线拆分槽并维护所有 LOD 对应，或编写自定义 SceneProxy / 渲染 Pass；后者涉及额外绘制、动画/LOD/蒙皮/遮挡和 Cook 验证，本次未引入。

## 渲染与兼容细节

- Hull 继续使用 VertexNormalWS 外扩、双面材质中的正面像素丢弃与深度测试。没有加入未实现的 Normal Source 枚举；平滑法线、反向法线修复及封闭 Section 边线没有被伪装为已有能力。
- Screen 继续使用 SceneColor、SceneDepth、CustomDepth、Stencil。没有 WorldNormal 内部结构边缘。不同组各执行一次后处理，IsBlendable=false 防止同主材质 MID 的参数被平均。相同最终参数的槽在同组件内共用辅助组。
- 源组件隐藏状态、材质隐藏状态和强制 LOD 同步到辅助网格；Skeletal 设置 Leader Pose 和父 LOD 同步。负数/零缩放的 Hull 明确拒绝；正非均匀缩放、极端宽度与剔除边界仍需人工观察。
- 新属性默认 false，旧 Preset v1 继续采用均匀壳宽度。Preset 仍仅保存风格，Actor 引用/Scope/覆盖保存在关卡。ApplyPreset 更新基础值并保留局部规则，失败时还原前值。
- 旧单槽绑定与新协调组件互斥，避免重复描边。运行时不依赖 UnrealEd 或 Python。后端材质通过硬引用保存 Cook 收集入口；完成编译不代表已经完成 Cook 验收。
- 缓存 `r.CustomDepth` 查询，消除每帧反复查找警告。辅助组仍在配置变化时重建；独立区域数量增加会增加网格绘制与全屏后处理成本，尚未给出性能预算。

## 验证证据与边界

已人工查看原始 Unified / Independent / Occluded 图像。统一外轮廓为 1661 个红色像素；独立区域为 1155 个红色、858 个绿色像素，交界描边可见；前景遮挡后为 1115 个红色像素，遮挡物中心检查区域为 0 个描边像素。这些数字用于受控场景验收，不是任意角色的画质或性能承诺。

最终构建、检查计数、像素结果及进程记录见同目录 `Validation.json`；原始结果在 `Validation/Create/Results.json`、`Validation/Reopen/Results.json` 和 `Validation/Legacy/`。检查按“数据与执行链”“实际图像”“未验收范围”分别记录。

最终结果：Editor / Game Development 构建通过；多粒度 Create 47/47、独立进程 Reopen 与整组预览 18/18；原单槽 Create 35/35、独立进程 Reopen 15/15；多粒度场景像素 5/5、整组人物预览像素 4/4、原单槽像素回归 5/5。运行时动画采样中，导入角色骨骼最大移动约 6.07 cm，两个辅助骨骼组件与各自源组件的位置误差为 0。

整组预览导出证据位于 `Validation/Reopen/GroupPreview*` 与 `TexturedCharacter/`。None 下左右图 RGB 平均误差为 0；红色/绿色变化检查扣除了相同视口坐标轴的颜色像素，避免将坐标轴计为残留描边。灰色验证表面的形体检测同时接受中性灰与较暗像素，不假定人物一定比背景更暗。

| 场景 | 验证方式 | 实际边界 |
|---|---|---|
| 单 Mesh / 单 Section | Engine Sphere 与单槽旧工作流 | 实际渲染与参数回归 |
| 单 Mesh / 多 Section / 多 Slot | 专用双区域 OBJ 导入为一个 Static Mesh | 读取两个真实 Section 和槽，两个后处理组 |
| Section 与 Material 优先级 | 单 LOD 独占槽 Section 覆盖 Width | Section 宽度覆盖 Material，Material 颜色继续继承 |
| 不同 Section 共用 Slot | 专用副本把第二 Section 映射到槽 0 | Material 共用风格成功；独立 Section 覆盖拒绝 |
| 多组件逻辑角色 | 相交部件、互补分区的导入角色组件 | 相同组 Stencil / 单 Pass，独立颜色与局部关闭 |
| Skeletal 动画 | 真实 AnimSequence 的两个明确时间点 | 比较骨骼确实移动，再检查辅助骨骼与源的误差；不是只检查指针 |
| LOD | Static 两级资源强制切换、Skeletal 强制 LOD 同步 | Skeletal 的真实多级自动过渡尚未验收 |
| 遮挡 / 交界 | NoOutline / Unified / Independent / Occluded 原始 PNG | 前景中心区域不误画轮廓；不代表任意视角完整验收 |
| 预设与场景保存 | 新 UE 进程重开 | 辅助对象重建、基础预设和组件引用保存 |
| 原单槽兼容 | 原 Create / Reopen / 像素脚本 | Hull / Screen / 颜色 / 宽度 / None / 保存恢复链路 |

开发过程中暴露的接线错误、编辑器动画不自动推进、全黑曝光图等均未计为通过：修复接线后重新编译；显式求值动画后再比对；加入固定曝光和灰色自发光测试表面后才进行像素验收。原始 PNG 未做裁剪、重绘或后期修补。

角色预览曾因 ShowGroup 清空单槽预览而未加载组合组件，导致空白。现已补齐整组复制、同步、聚焦与导出，并增加双组件数量、关闭描边、颜色/宽度实时变化及真实带纹理人物的导出检查。角色 Details 隐藏无关的组件继承字段与后端资源字段，原单槽专用的材质选择和转换按钮在角色模式禁用。

最终普通编辑器会话已选中 `Outline_TexturedCharacter`，无持续 Python 验证提示；[原生界面截图](UI_CharacterReady.png) 直接保存自 UE，未做图像修改。

尚未验收：任意复杂角色的所有相机角度、硬法线接缝、极小网格与最大壳宽度、正非均匀缩放、Skeletal 自动多级 LOD 过渡、Morph/布料/Deformer、原表面 WPO、组件 Mesh Paint 颜色覆盖、顶点颜色渐变图像、长时间编辑与性能、Cook/打包后视觉。原生面板的完整鼠标交互/撤销流程也需要人工验收；当前自动化共用服务与属性系统。
