# Outline 多粒度审查与设计

审查基线：2026-10-17，UE 5.8.3，本文件的“原实现”指本次增量开发之前。

| 控制粒度/能力 | 原实现支持情况 | 实现位置 | 发现的问题 | 方案 |
|---|---|---|---|---|
| Actor / Character | 无 | UNPROutlineComponent | Actor 只拥有单槽绑定，没有统一配置 | 新增角色协调组件 |
| Mesh Component | Skeletal 单组件、单槽 | RefreshOutline / UseSelection | UI 拒绝多主组件；不接受 Static | 显式组件列表，Skeletal 与普通 Static 辅助网格 |
| Section / Sub-Mesh | 不支持独立配置 | RefreshOutline 的 SetMaterial | Section 不等于 Slot | 查询所有 LOD 的真实映射，受限 Section 选择，拒绝共享槽歧义 |
| Material Slot | 单槽链路已接通 | ConvertMesh / OutlineMID | 多绑定会有后处理实例混合风险 | 逐槽参数解析，独立后处理实例禁用 Blendable 混合 |
| 局部顶点控制 | 无 | create_outline_backend_assets.py | 只使用 VertexNormalWS | 可选 VertexColor.R 宽度因子，默认关闭 |
| 多 Mesh 统一描边 | 无 | 独立 Stencil / PostProcess | 内部边界与重复处理 | 同组相同 Stencil + 一次 Screen Pass |
| 混合控制与参数覆盖 | 无 | Preset.Settings 整体复制 | 没有字段级继承 | Actor → Component → Material → Section，顶点因子最后乘 |

## 实际渲染路径

旧单槽：EditorLibrary::ConvertMesh 创建继承完整原表面材质的 MIC；UNPROutlineComponent::RefreshOutline 创建全尺寸辅助 SkeletalMesh，LeaderPose 跟随原骨架，只有目标槽使用 Outline MID，其他槽为 Visible=0 的 Mask。

Hull：M_OutlineHull 的 VertexNormalWS × WidthCm 接 WPO；TwoSidedSign 取负接 OpacityMask。它在双面材质中丢弃正面像素，并非单独修改引擎 raster cull mode。正常深度测试，无投影。原始顶点法线不连续处仍可能裂缝；未包含平滑法线导入、布料与原表面 WPO 复现。

Screen：M_OutlineScreen 后色调映射自定义 HLSL，使用 SceneColor、SceneDepth、CustomDepth、CustomStencil；16 方向×4 半径采样，仅向目标 Stencil 外扩。没有 WorldNormal、深度内部结构边缘、Section ID buffer。源组件已经写 CustomDepth 时旧路径拒绝。Stencil 为世界内扫描分配 1..255，并非全局独占协议。

UE 源码证据：SkinnedMeshComponent.cpp::ShowMaterialSection 最终更新 HiddenMaterials[UseMaterialIndex]，SectionIndex 只用于 LODMaterialMap 重映射，不能隔离共用槽的 Section。Material.cpp::OverrideBlendableSettings 依据 Base->bIsBlendable 查找已有同源后处理节点；多实例必须设置 bIsBlendable=false 才能独立执行。

仓库无独立 USF/USH/HLSL 文件；插件 HLSL 位于 Tools/create_outline_backend_assets.py 的材质 Custom 节点。EndfieldRender 的原有材质资产另行导出审计，其存在不代表已接入本插件。

### 二进制材质审计补充

`MultiScope/AssetAudit/Index.json` 和 11 份文本由 UE 读取真实资产导出，包含父实例链、材质输出连接、节点输入连接及引用的 Material Function。

- `M_Backface_Outline`、`M_Outline` 以及引用它们的 `MI_BF_Outline_Simple`、`MI_Chen_Outline_Main`、`MI_Outline_B/H/Skin` 是原内容包资源。图内存在顶点颜色、顶点法线、Scale、纹理 Mask、颜色及相应静态开关；`M_Backface_Outline` 还有顶点/像素法线选择与 TwoSidedSign 分支。节点通过 Material Attributes 输出。它们没有接入本插件的 FNPROutlineSettings / Actor 协调路径，不能将这些静态开关算作插件已有功能，也没有修改这些资产。
- `PPMI_Outline` 实际父材质为 `PPM_RimLight`，图内有 PostProcessInput0、DiffuseColor、CustomStencil 与自定义采样代码。没有将文件名解释为已实现独立 Section 边缘提取；具体连接保留在导出文本，原内容包的使用与新插件 Screen 材质分开。
- 插件三份材质通过同一生成脚本更新；新增顶点分支后仍保留原 Hull、Mask、Screen 算法。`UseVertexColorWidth=0` 保持旧外扩行为，Screen 的 IsBlendable=false 用于独立后处理组。

## 增量设计

保留 UNPROutlineComponent、既有接口、v1 Preset、原窗口及单槽转换。新增 UNPROutlineActorComponent 负责逻辑角色分组，复用 FNPROutlineSettings 和三份后端材质。角色配置独立保存到关卡；Preset 保持风格值快照，不保存场景对象引用。

Algorithm 继续使用 Method；Scope 分为 UnifiedSilhouette 和 IndependentRegions。后者通过是否配置 Component / Material / Section 覆盖表达 B/C/D 模式，避免增加行为重复的枚举。Unified 必须 ScreenSpace，启用区域必须同风格，允许局部关闭；违反条件报错。

字段覆盖按 Actor BaseSettings → Component Override → Material Slot Override → Section Override；未勾选的字段继承父层。Enabled 单独逐层覆盖，最终 Method=None 也关闭。顶点红色通道只控制 Hull 宽度，默认关闭，未导入顶点色的网格应先确认白色默认值。

Section 选择为明确 (LOD, Section)；当前材质辅助网格路线只能在该 Section 独占槽且该网格只有一个 LOD 时安全降为材质槽执行。多 LOD Section 身份映射及共享槽独立控制明确拒绝；Component/Material 级照常使用原资源 LOD 映射。要支持这些 Section 情况，需要内容管线拆槽并建立 LOD 对应，或自定义代理/Pass，本次不引入。

Unified：所有启用区域的辅助 Mesh 共用一个 Stencil，一个后处理实例；中心像素属于同组即不画内部边。Independent：每个目标组件内相同最终参数的槽共享辅助 Mesh，不同参数使用独立组；屏幕空间不同组可产生可见内部边。Hull 使用几何外扩，不保证每个 Section 都出现封闭边线。

不改原组件材质、CustomDepth 或网格资产。旧单槽和新角色组件不能同时控制同一 Actor，避免重复描边。仅接受 Opaque 覆盖；Mask、Translucent、源材质 WPO/布料/自定义 Deformer、Nanite 与 InstancedStaticMesh 需专门适配，不能自动推断覆盖。
