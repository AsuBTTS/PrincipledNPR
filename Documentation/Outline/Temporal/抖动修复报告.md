# Outline 抖动分析与修复

环境：UE 5.8.3，DX12 / SM6，2026-10-17。

## 原因

旧版 `M_OutlineScreen` 位于 After Tonemapping，晚于 TSR/TAA。它读取的 CustomDepth/Stencil 在默认 `r.CustomDepthTemporalAAJitter=1` 时逐帧偏移，而生成的硬边轮廓已经错过时间抗锯齿。这使静止物体也会出现轮廓位置、面积的逐帧变化。不是仅凭截图推断：旧版 32 帧对照中，描边红色分量的平均帧间变化为 **44.10 / 255**；同场景原画面为 **0.205 / 255**。单独关闭 CustomDepth jitter 后降为 **0.410 / 255**，确认采样时序是主要原因；这个关闭选项只用于诊断。

[Epic 的 Post Process Materials 文档](https://dev.epicgames.com/documentation/unreal-engine/post-process-materials-in-unreal-engine?lang=en-US) 描述了相同的后处理轮廓抖动，并建议提前到时间超分之前。[TSR 文档](https://dev.epicgames.com/documentation/unreal-engine/temporal-super-resolution-in-unreal-engine?lang=en-US) 说明 TSR 位于景深之后。

## 修改

- Screen 材质改到 **Scene Color After DOF**。已对照本机 UE 5.8 `PostProcessing.cpp`：此位置早于时域上采样；Before Bloom 已经晚于 TSR，不能用它代替。
- 保留 TSR/TAA 以及默认 CustomDepth jitter，使颜色、深度、Stencil 在同一时域采样下处理。
- 描边宽度仍用最终显示像素表示，乘以 `View.ViewResolutionFraction` 转换为内部像素；UV 步长取 `GetSceneTextureBufferSize(25).zw`，避免把共享渲染缓冲区尺寸和视口尺寸混用。
- 保留 UE 材质节点的自动预曝光处理，不手动重复乘预曝光。描边颜色现在与 Hull 一样进入 HDR、曝光和色调映射。
- 预览只在变换实际变化时设置世界变换。增加相机、渲染比例和辅助网格身份诊断接口，用连续真实视口帧验证，而非只比单张截图。

## 验证方法

`Tools/verify_outline_temporal.py` 在独立编辑器进程里，使用原来导入的贴图角色及完全相同的双视口预览。每组预热 90 帧，连续读取 32 帧；覆盖旧版、修复版、Hull、TSR 100% / 66%、TAA、1 / 3 / 8 px，以及黑色描边。

旧版材质保留为带验证标记的 `/Game/NPR/Outline/Temporal/M_OutlineScreen_LegacyBaseline`，只在验证场景中临时引用，不保存到角色绑定。测试不保存关卡。

离线脚本 `Tools/measure_outline_temporal.py` 不对帧做平滑，统计描边红色分量的逐帧变化，并以亮度归一化，避免色调映射改变颜色亮度造成假改善。运动测试每帧平移相机约 0.35 输出像素，补偿相机位移后再比较。原始 PNG、结果 JSON 和逐帧 GIF 保留在本目录。

## 验证结果

13 组、每组 32 帧，合计 **416 帧**。全部 **67 项**有界检查通过。统计来自同一进程、同一角色、同一相机的旧版与修复版对照。

| 场景 | 描边信号平均帧间变化 / 255 | 亮度归一化后的平均变化 |
| --- | ---: | ---: |
| 旧版 Screen，TSR 100%，静止 | 46.05 | 22.80% |
| 修复版 Screen，TSR 100%，静止 | 1.14 | 0.76% |
| 修复版 Screen，TSR 66%，静止 | 0.66 | 0.44% |
| 修复版 Screen，TAA 100%，静止 | 2.27 | 1.52% |
| Hull，TSR 100%，静止 | 2.99 | 2.45% |
| 黑色 Screen，TSR 100%，静止 | 0.70 | 0.70% |

静止 Screen 的归一化帧间变化减少 **96.67%**。相机每帧平移约 0.35 px 时，补偿画面位移后的变化从 **9.84% 降至 3.40%**，减少 **65.47%**；TSR 66% 对应为 **3.47%**。这是相邻帧信号变化的减少，不代表任意场景的全部抖动已经消失。

1 px / 8 px 均通过连续帧检查；3 px 描边在 66% 与 100% 下的信号面积差约 **4.0%**。黑色描边使用“原画面亮度减描边画面亮度”的信号单独检查。每组均确认真实视口持续重绘、AA 方法正确、预览辅助网格对象身份不变，没有用冻结画面获得低变化量。

回归：多组件角色流程 **18 / 18**，预览图像检查 **4 / 4**，旧单材质槽重开流程 **15 / 15**。真实材质着色器编译通过；编辑器 C++ 构建通过。

## 适用范围

这次针对已支持的 Opaque 几何和 Screen / Hull 描边。Masked / Translucent 覆盖、布料 / Deformer、原表面 WPO、外扩壳硬法线接缝仍沿用原来的支持边界。时间抗锯齿收敛需要若干帧，任意高速运动和所有角色的绝对无拖影不作未经实测的承诺。
