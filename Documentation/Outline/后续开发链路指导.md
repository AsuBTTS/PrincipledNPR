# 基于 Outline 闭环扩展 NPR 功能

## 可复用的数据与调用关系

```text
Editor 角色选择 / 材质槽选择
  → 统一转换服务（校验、创建实例、保存来源）
  → 持久角色绑定组件
  → 参数工作副本 → 双视口预览
  → 提交参数 → Runtime 更新
  → 保存纯风格预设 + 保存角色所在关卡
  → 新进程重开 → 重建临时渲染资源
```

Outline 的窗口、编辑器 Python 和验证脚本调用同一套 `UNPROutlineEditorLibrary` 服务。后续功能也应共享服务，不为 UI 和脚本实现两套转换逻辑。

## 每个功能保留四类对象

| 对象 | 存储什么 | 不应混入什么 |
|---|---|---|
| 参数设置 | 有明确单位和范围的可编辑值 | 角色槽号、原始网格 |
| 风格预设 | 参数快照与 Schema 版本 | 当前角色的贴图和骨骼事实 |
| 角色绑定 | 网格、稳定槽名、原材质、生成材质、应用后的参数 | 进程内临时 MID/辅助网格 |
| 后端资源 | 实际材质、Shader、编译结果 | 未经映射的语义数值假设 |

当前 Outline 使用独立的强类型 `FNPROutlineSettings`，支持颜色和不同单位的宽度。既有 `FNPRParameterPatch` 仍是标量骨架；后续统一 StyleProfile 时，应建立类型化覆写/子设置接口，不能把 RGB 压成一个 Float，也不能将 `HullWidthCm` 偷换成 `OutlineWidthPx`。

## 新功能的开发顺序

1. **冻结参数与输入合同。** 写清单位、范围、缺省值、支持的材质种类、所需资源，以及非法输入如何反馈。Face 的头部坐标、Hair 的流向属于绑定事实。
2. **先实现实际渲染后端。** 用一个受控槽证明参数确实改变画面。Diffuse、Specular、Face 和 Hair 需要自己的映射/标定，不能把 Outline 的材质继承误称为 PBR 到 Toon 的完整转换。
3. **将后端接到 Runtime。** 参数更改只更新必要资源。生成的临时 MID、辅助组件应在注册时重建，在取消注册时释放，并为 Cook 保留明确的资源引用。
4. **加入统一转换服务。** 原材质/贴图可追溯、只操作选中槽、重复执行幂等、失败先诊断。支持范围外的源材质应拒绝或请求显式映射，不凭参数名猜测后默默丢贴图。
5. **复用工作副本与对比视口。** 左侧来源、右侧目标保持同几何、同相机、同灯光；临时调参和持久提交分开。属性提交加入编辑器事务。
6. **预设与绑定分别保存。** 风格跨槽应用时重新建立目标绑定；重开不依赖某次工具窗口留下的内存对象。
7. **跑真实闭环。** 构建、Shader 完成、图像变化、原材质保留、单槽隔离、保存、新进程重开分别取证。

## 参数更新路径必须明确

- 普通 Scalar / Vector / Texture 可走 MID 更新。
- ToonProfile 等不可变后端资源需要编辑期生成、刷新或预制包切换；必须验证实际刷新成本。
- 离散策略切换需要验证资源重建和清理。
- 禁止把编辑器中的资源生成接口放入 Runtime 模块，或在 Runtime 中依赖 UnrealEd。

## 最小验收清单

- 选中角色、槽位及转换结果可追踪；原材质和纹理引用保留。
- 参数单位明确；颜色、数值和方式均保存到预设与绑定。
- 失败不会改变其他材质槽；恢复操作不会覆盖其他系统的改动。
- 重复转换不生成重复绑定；方法切换后没有残留辅助组件。
- 画面对比证明参数有实际效果，宽度和颜色测试具有可判读的图像证据。
- 关闭后用第二个编辑器进程重开，状态与已保存资产一致。
- 记录明确支持范围，不把编辑器构建通过或 NullRHI 冒烟当作 GPU 渲染通过。

这套指导可承接 Diffuse、Specular、Normal、Rim、Face 和 Hair；每项仍需自己的后端能力与资产验证，尤其不能从 Outline 的闭环推出所有 NPR 模型已经可用。
