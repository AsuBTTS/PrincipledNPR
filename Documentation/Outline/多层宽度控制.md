# Outline 多层宽度控制

## 评估结论

当前后端是反向壳（Inverted Hull）和 CustomDepth/Stencil 区域扩张（Screen Space）。两者都没有完整的边缘来源分类缓冲区。因此，本次增加可执行的宽度分层和能力查询，保留算法边界。

| 边缘来源 | 当前识别/生成能力 | 宽度入口 |
| --- | --- | --- |
| Silhouette | Screen 生成所选 Stencil 区域轮廓；Hull 用背面壳形成视角相关轮廓 | 基础宽度 × Silhouette 倍率 × 区域倍率 |
| Crease（几何折痕） | 不支持：没有三角形邻接/二面角分析，也没有法线梯度折痕检测。Hull 的硬法线接缝不能当作 crease 分类 | 不提供无效的 crease 倍率；可用局部入口调节已有轮廓，不能凭宽度控制生成内部折线 |
| Occlusion（遮挡边） | 不支持独立分类/生成。Screen 的深度比较只抑制被前景遮挡的线，Hull 接受普通深度遮挡 | 不提供独立 occlusion 倍率；不能将 Depth Bias 当作遮挡边宽度 |
| Material / Feature Boundary | Screen + Independent Regions 可生成手工划区的轮廓；不自动识别材质语义、纹理边界或语义特征。Hull 不能仅凭材质切分生成内部边界线 | 手工指定 Feature Boundary，使用其倍率；Material Slot / 受限 Section 决定区域 |

同一解析区域只选择一种宽度来源，当前不是在同一像素自动分类四种边。`GetEdgeCapabilities(Method, Scope)` 返回四类来源的自动/手工支持状态和限制；窗口也显示简短说明。Crease / Occlusion 在枚举中保留用于能力查询，但不作为可编辑来源；通过程序提交这些来源会明确报错。

## 宽度合成

```text
区域常量宽度 = 基础宽度 × 当前边类型倍率 × 区域宽度倍率
Hull 顶点宽度 = 区域常量宽度 × 顶点色因子 × Mask 因子
Screen 宽度   = 区域常量宽度
```

- 基础字段仍为 `WidthPixels` / `HullWidthCm`，分别用输出像素和厘米计量。
- 新增 `WidthEdgeSource`、`EdgeWidthScales.Silhouette`、`EdgeWidthScales.FeatureBoundary`、`LocalWidthScale`。
- 边类型与区域倍率范围均为 0～4。合成后上限仍为 Screen 8 px / Hull 5 cm，超限会报错；不在校验中静默截断。
- 区域常量宽度为 0 时移除该区域的辅助描边，而不是留下零宽重叠壳。
- 关闭 Vertex / Mask 控制时相应因子为 1。启用时分别使用 `saturate(VertexColor.R)`、`saturate(WidthMask.R)`；两者同时启用则相乘。
- 默认基础宽度已收细为 **Screen 1.25 px、Hull 0.1 cm**，新增倍率默认 1。当前演示角色及其自有预设同步收细。

例如：Screen 基础 1.25 px、Silhouette 倍率 1，某头发材质槽区域倍率 0.8，得到该区域 1 px 的采样半径。它是光栅扩张距离，不保证所有视角下都具有严格 1 px 的可见线厚。

## 区域继承与覆写

```text
Actor.BaseSettings → Component.Override → Material Slot.Override → Section.Override
```

只有勾选的字段替换继承值，最深层生效；区域倍率不逐层累乘。

| 覆写开关 | 修改内容 |
| --- | --- |
| 原有 `bOverrideWidth` | 替换基础像素/厘米宽度，保留原接口 |
| `bOverrideEdgeSource` | 替换当前区域的来源标签 |
| `bOverrideEdgeWidthScales` | 替换整个边类型倍率表 |
| `bOverrideLocalWidthScale` | 替换区域倍率 |
| 原有 `bOverrideVertexControl` | 替换顶点色开关 |
| `bOverrideWidthMask` | 同时替换 Mask 开关与纹理 |

`ResolveRegions()` 增加 `ResolvedWidth` 和 `WidthParameterSource`，可以查看 GPU 细化之前的宽度及各字段的继承来源。旧预设仍用 v1，新增字段采用默认值；没有批量改写用户预设。

### Material Slot

使用稳定且唯一的槽名。例如，给 Hair 的 Material Rule 勾选“覆写区域宽度倍率”，将 `Values.LocalWidthScale` 设为 0.8。它调节该区域已有轮廓的宽度。

需要手工材质边界时，将 Scope 设为 Independent Regions，Method 设为 Screen Space，并将对应区域 `WidthEdgeSource` 设为 Feature Boundary。此类区域即使样式相同，也按材质槽分别建立组，避免合并后丢失边界。

这是区域掩码边界，不是几何/语义分类。两个区域对共享边分别向外扩张时，可能形成双侧线条；应降低 Feature Boundary 倍率。隐藏区域、未画入 Stencil 的区域、其他遮挡者仍影响可见结果。

不同的区域宽度会拆分 Stencil 组，可能在区域交界产生接缝；这与一个统一 Stencil 中的连续变宽具有不同结果。

### Section

继续只支持**单 LOD 且独占材质槽的 Section**。共享一个槽的多个 Section 不能独立控制；多 LOD 没有稳定身份映射时也会拒绝。需要先在资产中拆分槽，或使用 Material Slot 控制。

### Vertex Color（Hull）

在网格资产的 R 通道绘制宽度因子：0 缩到零，1 保持区域常量宽度。当前读取资产顶点色，不复制组件 Mesh Paint 的颜色覆盖。顶点色只改变壳的位移，不增加新的内部特征线。

### UV Mask（Hull）

启用 `bUseWidthMask`，指定 `WidthMask`。要求 Texture2D、Compression = Masks、sRGB = false、非 Virtual Texture。使用 UV0 的 R 通道，显式 mip level 0，在顶点阶段采样。

Mask 细节受网格顶点密度和 UV 接缝限制，不能以高分辨率贴图替代几何细分；流式纹理也受实际驻留 mip 限制。建议使用小尺寸并常驻的宽度 Mask。自有白色默认纹理只用于关闭 Mask 后复位，不修改 Engine 的纹理。

### Screen 与 Unified Silhouette 的限制

CustomDepth/Stencil 没有携带连续的顶点宽度或 UV Mask 数据，因此 Screen 中启用这两项会报错。若需要连续局部宽度，应使用 Hull，或先将区域离散成不同 Material Slot / 可控 Section 并使用各自常量宽度。Screen 的连续属性控制需要额外的属性缓冲区与渲染通道。

Unified Silhouette 仍要求整组一致的样式和宽度，只允许局部关闭；不能同时保留一个统一 Stencil 又使用不同局部宽度。局部差异、手工 Feature Boundary 需 Independent Regions。Screen 仍位于 DOF 后、TSR/TAA 前，保留此前的采样时序修复。

## 资产更新与完成状态

`Tools/create_outline_backend_assets.py` 构建 Hull 的 Mask 节点和自有白色纹理；`Tools/update_outline_width_assets.py` 在编译插件后运行一次，更新这些资产，并仅将带归属标记的演示角色及其预设设为 1.25 px / 0.1 cm。普通打开项目不需要运行脚本。

本次完成源代码扩展、界面说明与资产更新。C++ 构建和实际材质编译结果记录于 `Saved/Logs/NPR-WidthLayers-*` 与 `Saved/NPR/Outline/WidthAssetUpdate.json`。**本次未运行自动化测试或新的图像回归**；此前的多粒度/时间稳定性结果是历史记录，不能当作本次新增 Mask 与分层功能的验收。
