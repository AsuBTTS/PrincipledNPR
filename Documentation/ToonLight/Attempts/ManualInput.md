# 实机视口输入检查

2026-10-29，用户关闭 UnrealPak 防火墙提示后，我们在独立关卡副本 `/Game/NPR/ToonValidation/L_ToonWorkspace_20261029_153354` 中检查实际 NPR 调制窗口。右侧列表选择脸部槽 6 成功，但鼠标直接点击服装后仍停留在槽 6；[真实失败截图](ManualInputInitial.png)保留当时状态。

此前自动化调用 `GetHitProxy → ProcessClick`，只覆盖末端选择与映射，未覆盖真实视口输入链。源码中的 `ProcessClick` 重写不足以保证 UE 5.8 资产预览工具将单击送到这里。

中间尝试给 `InputKey` 增加普通左键处理。对应的 SceneViewport 输入自动化八项成功，但实际桌面点击仍未切换，因此这版没有被接受为完成。其[原始结果](InputKeyOnly/Automation.json)另存，并保留其中一条 UE 联网检测 HTTP 超时警告；不能把 8 项成功概括为零警告。

最终方案在 Slate 控件的 `OnPreviewMouseButtonDown` 和捕获后的释放事件接收普通左键，按实际视口控件几何换算归一化坐标，再读取 Hit Proxy；拖动超过 4 像素不切换，Alt/Ctrl/Shift、右键和中键继续走原输入。其他页面没有区域回调，原流程不变；丢失捕获时清理状态。

自动化同步改为 `Slate RoutePointerDown/Up → 视口控件 → 几何坐标转换 → Hit Proxy → ProcessClick`。最终实机和自动化结果见验证报告。本文保留失败经过，不把早期通过结果追溯扩大为整条输入链已经验证。

诊断进一步确认：事件已经到达控件，坐标一致，也有 Actor 命中；组合预览命中了描边辅助网格，旧映射只识别源副本。仅在测试副本中关闭描边后，同一脸部点击立即选到槽 6。最终沿辅助网格的附着关系回溯到源副本，保留描边后实际点击脸部、服装分别选到 6、2。夹具同步复制真实角色的描边配置并确认辅助网格存在，最终 13 项自动化通过。
